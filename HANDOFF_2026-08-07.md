## For the paper — content worth citing

### 1. A second Qwen hallucination pattern: unfamiliar proper noun → familiar phrase

New finding, same underlying cause-family as the grammar-normalization
limitation already documented on 2026-08-06 (language-model prior overriding
uncertain visual evidence), but a distinct failure mode worth citing
separately: when handwriting for an **uncommon proper noun** is ambiguous,
Qwen2.5-VL doesn't produce a garbled/partial read — it substitutes a
**common, familiar phrase** instead. Concretely: two different students,
different handwriting, different source photos, different crop coordinates
(confirmed via direct database/file inspection — not a caching bug) —
both got "Homonhon" (the correct answer, an uncommon place name) misread as
"**Honor Roll**", a common English phrase with no visual relationship to the
correct word beyond superficial letter-shape ambiguity.

Why it's citable: it's a second, independent piece of evidence for the same
"pretrained-model dependency" limitation category, strengthening that
section with a concrete, reproducible example beyond the single
grammar-normalization case already written up. The system's flagging safety
net caught both instances correctly (auto-flagged `identification_no_match`,
scored 0) — worth noting the mitigation worked even though the underlying
model behavior wasn't fixable.

### 2. RQ4 flagging mechanism: a real gap found and closed mid-testing

While testing MCQ grading, found a genuine case where the confidence-gap
flagging heuristic (flag if `confidence < 30%`) failed to catch an invalid
answer: a student filled one MCQ bubble fully and left a partial/half-shaded
mark on a second option. The fill-ratio *gap* between the two bubbles was
large enough to produce 43.7% confidence — comfortably above the 30%
threshold — so it was **never flagged**, even though the mark was genuinely
ambiguous (arguably invalid). Fixed by adding a second, independent check:
if 2+ bubbles clear the minimum fill threshold *at all* (regardless of the
gap between them), it's now automatically scored wrong and flagged with a
distinct reason (`omr_multiple_marks`).

Worth a sentence in Methodology: the flagging system was iteratively
hardened during testing to catch a class of invalid-mark error the original
confidence-gap-only design missed — i.e., testing surfaced a real
methodological refinement, not just implementation bugs.

## Technical summary — what changed today (for your own reference)

1. **OCR-correction step leaking its own commentary into stored answers**
   (`ai_grader.py`). Root cause: `llama-3.3-70b-versatile`, used for
   post-OCR layout cleanup on essay/identification answers, sometimes
   ignores its instructions and narrates its own output instead of just
   returning cleaned text — e.g. *"However, the above response still has
   run-on lines. Here is the reformatted text:"* got stored as if it were
   part of the student's answer. Worse case: for a short identification
   answer, the model's uncertain self-reasoning (*"Treaty of Maastricht does
   not match, however a possible correction is..."*) became the literal
   graded answer. Fixed with defense-in-depth: strengthened both correction
   prompts against self-narration, plus a `_looks_like_runaway_correction()`
   guard that detects known leak patterns and falls back to raw OCR text
   (same fail-safe pattern already used for API errors). Verified against
   the actual captured bad outputs from today's test run, and re-verified
   end-to-end after the user reprocessed both affected submissions — clean
   text now, scores changed accordingly (e.g. essay 21→23.5/25 once graded
   against real content instead of padded garbage).

2. **MCQ/TF multi-mark safety net** (`omr_engine.py`, plus all three grading
   call sites — `routers/api_v1.py` single-submission, `routers/api_v1.py`
   bulk process, `job_queue.py` background worker). See "RQ4 flagging" above
   for the motivating case. `detect_omr()` now returns a distinct
   `"Multiple bubbles marked"` sentinel when 2+ bubbles clear
   `MIN_FILL_RATIO`, which all three grading paths score as an automatic
   zero and flag as `omr_multiple_marks` (separate from generic
   `omr_low_confidence`). Verified against Carlos Espiritu's real MCQ1 scan
   (Q1: B fully filled + D crossed-out/scribbled — previously scored
   *correct* by accident since B's fill ratio narrowly won; Q2: B fully
   filled + C half-shaded — previously scored correctly but silently,
   43.7% confidence never tripped the old flag threshold). Both now
   correctly flagged. Regression-checked a clean single-fill answer to
   confirm normal MCQ/TF detection is unaffected.

3. **Identification result display** (`frontend/src/pages/ResultsPage.jsx`).
   The "Result" section was dumping one run-on sentence — `"Expected:
   Lapulapu. Your answer: Lapu Lapu. Accepted (fuzzy match 94%)."` — as a
   single paragraph, duplicating info already shown elsewhere on the card.
   Added `parseIdentificationResult()`, which parses the backend's sentence
   back into parts (falls back to the raw sentence if the format ever
   changes) and renders a scannable Expected / Your answer grid plus a
   color-coded verdict badge (exact/accepted = green, partial = amber,
   incorrect = red). Also removed the now-redundant standalone "Expected:"
   line that duplicated this once grading exists (kept for the pre-grading
   state, where there's no `ai_feedback` yet). Verified the parser against
   all real feedback strings captured this session, including edge cases
   (blank answer, no-percent exact match).
