## The core confusion this resolved first

- Essay grading uses **Groq (Llama-3.3-70B-Versatile)**, not Qwen. Qwen is OCR only
  (handwriting → text). Groq/Llama does the actual grading.
- Current grading = **zero-shot rubric-conditioned prompting** — no training, no
  fine-tuning. This is why the panel's "classification model" note landed: there was
  no trained artifact anywhere in the essay-grading path.
- Groq only allows fine-tuning for **Enterprise customers by request** — not available
  to this project. Confirmed via web search. This rules out fine-tuning Llama-on-Groq
  entirely, not just as a preference.

## The solution: a new, separate, genuinely trained classifier

Sits **alongside** the existing Groq grading — does not replace or retrain it.

**Model**: Ordinal logistic regression (respects the natural order Poor < Fair < Good
< Excellent; appropriately small for the dataset size; fully interpretable — 6 total
learned numbers).

**3 inputs** (all already producible from the AI grader's own output on an essay):
1. AI's overall score, as a % of max points
2. AI's average confidence (self-reported by the LLM)
3. Spread — how much the AI's per-criterion scores disagreed with each other

**Formula**: `z = β1(score%) + β2(confidence) + β3(spread)`, compared against 3
learned threshold values to classify into one of the 4 bands.

**Why these 3 inputs specifically**: score% says *what* the AI concluded; confidence
and spread say *how much to trust* that conclusion. Same underlying idea as LLM-Rubric
(Hashemi et al., 2024) — a small trained layer that combines a zero-shot model's raw
judgments with reliability signals, rather than trusting the raw output blindly.

**Ground truth bands** use fixed % cutoffs (90/75/60) applied consistently across all
essays, since different professors' rubrics have different point scales — everything
gets normalized to % first.

## Code changes already made in this repo

1. **[ai_grader.py](ai_grader.py)** — broadened the AI's self-reported confidence
   instruction (both the legacy single-score prompt and the structured per-criterion
   prompt) so confidence reflects **both** OCR clarity **and** how clear-cut the
   rubric judgment is — not OCR quality alone. This matters because OCR is already
   accurate in this system, so confidence was clustering near 1.0 and carrying little
   signal. Now it should vary more meaningfully, which matters since it's a classifier
   input.

2. **[classification_model.py](classification_model.py)** (NEW) — the full pipeline,
   built and tested end-to-end:
   - `load_professor_grades()` / `build_professor_grades_template()` — reads/creates
     the long-format CSV professor grades get consolidated into
   - `get_ai_features_for_essay()` — calls the real `grade_essay()` from
     `ai_grader.py`, reduces its output to the 3 classifier inputs
   - `assemble_training_table()` — merges AI features with ground truth; **correctly
     handles Part 1 (single-rater) vs. Part 2 (5-rater average)** — verified this
     computes correctly with a manual test
   - `train_ordinal_classifier()` / `cross_validate()` — fits with k-fold
     cross-validation (via `statsmodels.miscmodels.ordinal_model.OrderedModel`)
   - `evaluate_predictions()` — exact accuracy, adjacent agreement, confusion matrix
   - `python classification_model.py` runs a self-test on **synthetic** data —
     confirmed working (75.3% exact accuracy, 99.3% adjacent agreement on fake data —
     not real results, just proof the mechanics work)

3. **[professor_grades_template.csv](professor_grades_template.csv)** (NEW) — example
   rows showing the exact format needed: `essay_id, part, professor_id,
   question_prompt, essay_text, criterion_name, criterion_max_points,
   criterion_score`.

4. **[requirements.txt](requirements.txt)** — added `pandas`, `statsmodels`,
   `scikit-learn`.

**Still needed before real training can run**: each professor's actual rubric

## Data collection plan (final version)

Three parts, all from the same 5 recruited professors:

**Part 1 — Live essay activity (own class, real system)**
- Each professor runs a normal essay activity through GrAId (~25 students each ≈ 125
  essays total) — real handwriting, real OCR, real scanning
- Professor grades the same essays **independently, per criterion, blind to the AI's
  score** (to avoid anchoring bias) — this becomes single-rater ground truth
- Produces: OCR accuracy (CER/WER) data, flagging precision/recall data (via the
  Confirm/Not-an-error review clicks), Essay Justification Quality ratings, AND the
  bulk of the classifier's training data

**Part 2 — Shared essay batch (async, all 5 professors, same 40 essays)**
- 40 essays sourced from the **PERSUADE 2.0 corpus** (not live-written — see dataset
  section below), sent to all 5 professors
- Each grades independently, per criterion, using their own rubric
- Ground truth = average of all 5 professors' scores per essay (consensus discussion
  if one professor is a clear outlier)
- Produces: inter-rater reliability check (validates that single-rater ground truth in
  Part 1 can be trusted) + a smaller, extra-reliable slice of classifier training data
- Files ready to send: `Part2_Shared_Essay_Batch.xlsx` (professor-facing, essay text +
  blank rubric columns, no scores shown) and
  `Part2_Batch_TEAM_REFERENCE_do_not_send.csv` (team-only, has original metadata) —
  **these were built in the scratchpad, not saved into the repo — regenerate or
  relocate if needed in a new session**

**Part 3 — Recorded interview (20-30 min, 9 questions)**
- Usability / trust / workload / adoption willingness — feeds thematic analysis for
  RQ4 ("How do General Education professors perceive...")

**Non-negotiable across all parts**: professors must grade **per rubric criterion**,
never just one holistic number — this is what makes the data usable for both the
Reference Score and the classifier.

- Final 40-essay batch: stratified across all 6 original holistic score bands (2,

## Explored and explicitly rejected (don't re-litigate without new input)

- **Switching target population to Senior High School teachers** — rejected;
  RQ4 explicitly says "General Education professors," and SHS likely means minors →
  real ethics/consent complications, not worth it this close to defense
- **Broadening beyond Gen Ed to technical/course-specific professors** — smaller,
  viable change if recruitment struggles persist, but still needs RQ4 wording update;
  not pursued yet
- **Using DREsS or other external analytically-scored datasets as MAIN training
  data** — rejected. Risk: classifier calibrates to the external raters' grading
  standards instead of this study's own 5 professors, which would undermine the
  entire comparison. Own data (125 + 40 = ~165 essays) is already a reasonable size;
  no real need for external supplementation right now.
- **Full cross-grading** (all 5 professors grade all 125 Part-1 essays) — rejected,
  5x workload; replaced with the Part 2 shared batch instead
- **Developers grading instead of professors** — rejected outright; breaks the
  study's core "AI vs. independent expert judgment" comparison
- **Skipping to demo + interview only** (no real grading data at all) — rejected;
  would lose almost every quantitative metric in the evaluation table, including the
  classifier

  truth + inter-rater check, AI feature extraction, classifier training, classifier

(reusing the same "within 1 point" standard already used for Essay Score Agreement,
citing Cizek & Page, 2003; Elliott, 2003) + confusion matrix, all interpreted against
the inter-rater agreement baseline (professors' agreement with each other) rather than
judged against an impossible 100% standard.

   2024) to show awareness that trained methods CAN be more accurate, and explain why
   they weren't used anyway (data/infra/time scope, not that they're worse in
   principle).
